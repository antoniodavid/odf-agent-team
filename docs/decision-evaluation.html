Decision evaluation

4 min read

ODF already records operational telemetry (duration, status, tokens) and a reference corpus of golden trajectories. This report adds a decision-quality view over evidence that is already on disk. It is a calibration tool, never a gate: it does not block, approve, or change workflow state.

#Run

node scripts/odf-evaluation.js decisions [days] [--root <dir>] [--md]
node scripts/odf-evaluation.js review <change> --route <correct|incorrect> \
  --risk <under|ok|over> --plan <under|ok|over> --gate <correct|incorrect> \
  --rating <1-5> [--root <dir>]
node scripts/odf-evaluation.js agreement [file] [--root <dir>] [--md]
node scripts/odf-evaluation.js compare <before.json> <after.json> [--md]
node scripts/odf-evaluation.js cadence [days] [--root <dir>] [--md]
node scripts/odf-evaluation.js proposals <report.json> [--md]
  • days (default 30) limits the metrics window.
  • --root points at the Odoo project root; the default is the current directory.
  • --md prints Markdown instead of JSON.

The command reads:

  • openspec/changes/*/state.yaml (canonical state, route, completed stages, entry_route_binding).
  • .odf/policy-gate-{change}.json (risk tier, gate stage, changed lines).
  • .odf/receipt-{change}.json (failure disposition).
  • .odf/attempt-ledger-{change}.jsonl (attempts, failures, rework).
  • .odf/override-{change}.jsonl (audited overrides).
  • The plugin metrics JSONL (delegations-YYYY-MM-DD.jsonl).

Engram-only changes are not read; the report warns and excludes them. It never reads prompts, diffs, source contents, credentials, or absolute paths.

#What it measures

Field Definition
route_agreement entry_route_binding.predicted_route === work_type; null when the binding is missing.
risk_tier Persisted Policy Gate risk_tier (LOW, MEDIUM, HIGH); null when no gate exists.
plan_mode Route plan (none, inline, required).
first_pass No failed attempt-ledger record and no receipt for the change.
rework_count Failed attempt-ledger records.
receipts Persisted failure dispositions (stage, role, status, cause, action).
override_count Audited override records.
stage_activity Calls, ok/blocked/error counts, total and average duration per stage role.
archived State canonical_stage === "ARCHIVED".

Aggregate output includes route agreement, risk-tier and plan-mode distributions, first-pass yield, rework rate, receipts by cause/status, override count, archive rate, and stage activity. Missing evidence is null/N/A or a warning; an empty workspace is no_data. The report never invents a value.

#Ground truth and limits

A decision is not "correct" because the harness says so. The report combines:

  1. Objective outcomes: first-pass, rework, receipts, overrides, archive, duration.
  2. Human labels (Phase 2): a local decision review at archive/verify.
  3. Reference trajectories: golden cases that protect a known defect.
  4. Semantic shadow (optional): human/judge agreement and false-pass rate.

Current limits:

  • It does not capture new decision records; it derives the report from existing evidence and the optional local review.
  • It cannot see post-merge defects or incidents; those require a manual label.
  • Route agreement requires a persisted entry_route_binding.
  • Engram-only changes are out of scope for this report.
  • verify-report is the VERIFY completion artifact; verify remains an alias for references but does not complete the stage.

#Guardrails

  • Local-only by default; no prompts, free text, diffs, secrets, or absolute paths in the output.
  • no_data/N/A honesty: never synthesize a score or a verdict.
  • Calibration only: no automatic gating, promotion, or route change. A human decides whether a metric becomes a gate.
  • The existing /odf-feedback remote submission remains opt-in, aggregate, and separate from this report.

#Local decision review (Phase 2)

At archive/verify, after the outcome is known, the orchestrator may ask four closed questions plus an overall rating:

  • Was the route correct? correct / incorrect
  • Was the risk tier adequate? under / ok / over
  • Was the plan mode adequate? under / ok / over
  • Did the gate block correctly? correct / incorrect
  • Overall rating: 1–5

It then runs the review command above. The artifact is <root>/.odf/decision-review-{change}.json; it is local-only, has no free text, and never blocks archive or changes workflow state. Re-running the command overwrites the label with a fresh reviewed_at.

The decisions report adds review coverage, route-correct rate, risk-fit and plan-fit distributions, gate-correct rate, and average rating.

#Human/judge agreement

agreement reads a shadow-judgment JSONL (default <root>/.odf/shadow-judgments.jsonl) and reports:

  • agreement (human and judge both pass or both fail)
  • false_pass (human fail, judge pass)
  • false_block (human pass, judge fail)
  • unavailable (no real judge verdict; excluded from agreement)

An empty or all-unavailable corpus is no_data; a mix is partial. This is calibration only: it never gates delivery, and promoting the judge to a gate remains an explicit human decision backed by measured agreement.

#Period comparison (Phase 3)

Save a baseline and compare it later:

node scripts/odf-evaluation.js decisions 30 --root <worktree> > before.json
# ... work for another period ...
node scripts/odf-evaluation.js decisions 30 --root <worktree> > after.json
node scripts/odf-evaluation.js compare before.json after.json --md

The comparison shows before/after values, deltas, direction, and whether higher is better for route agreement, first-pass yield, rework, receipts, overrides, archive rate, review coverage, human route/gate correctness, and average rating. It does not declare a winner; a human interprets the deltas.

#Review cadence (Phase 3)

node scripts/odf-evaluation.js cadence 30 --root <worktree> --md

Reports changes, reviewed changes, coverage, the latest review date, its age, and whether a review is due. due is true when no review exists or the latest review is older than the cadence (default 30 days). It is advisory and never blocks archive or verify.

#Improvement proposals (Phase 3)

node scripts/odf-evaluation.js proposals report.json --md

Deterministic rules turn report thresholds into proposals:

Rule Proposal
Route agreement < 0.8 route-alignment
Human risk fit under risk-underestimated
Human plan fit under plan-underestimated
Human gate-correct < 1 gate-review
Rework rate > 0.2 rework-hotspot
First-pass yield < 0.7 first-pass-yield
Review coverage < 0.5 review-coverage

Every proposal carries requires_human_approval: true and auto_apply: false. No route, risk tier, plan mode, gate, or file is changed automatically. A human decides whether to act, and a confirmed defect becomes a new golden.

#Phase 4 (not started)

  • Automated periodic reports/scheduling outside the harness.
  • Post-merge defect labels.
  • Engram-only change discovery for the decisions report.
